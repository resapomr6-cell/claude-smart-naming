# 输出治理 Output Governance

## 目的
治理 AI 智能体（Claude Code 等）工作过程中产生的一堆文件：乱命名、重复、临时、散乱。让输出从「机器随意吐」变成「人可控、可回溯」。

## 生命周期模型
```
生成(命名) ──▶ 组织(分类) ──▶ 活跃(使用) ──▶ 归档(回溯) ──▶ 清理(删除)
```

| 阶段 | 动作 | 引擎命令 |
|---|---|---|
| 生成 | 用内容摘要起名（见 smart-naming） | — |
| 组织 | 归入分类目录 | `organize` |
| 活跃 | 正常使用 | — |
| 归档 | 长期未动 → 移入 `归档/` | `archive` |
| 清理 | 删临时/垃圾文件 | `cleanup` |

另有 `scan`（体检）、`rename`（改乱名）、`dedup`（去重）。

## 引擎：govern.py
治理引擎在仓库根目录，用法：
```bash
python govern.py <command> [目录] [--apply] [--days N]
```

六个子命令：
- `scan`      扫描生成治理报告（只读）
- `rename`    重命名乱命名文件（读内容提标题）
- `organize`  按分类目录整理根目录文件
- `archive`   归档 N 天未动的文件（默认 30 天）
- `cleanup`   清理临时/垃圾文件
- `dedup`     按内容哈希识别并删除重复文件

## 使用规则（重要）
1. **先 `scan` 看报告**，再决定执行哪个动作。
2. **默认 dry-run**（只预览）；确认无误后才加 `--apply`。
3. `archive` / `cleanup` / `dedup` 是**破坏性操作**，执行前必须让用户确认。
4. `rename` 对无法提炼标题的文件会跳过并提示，交给 Claude 读内容后手动重命名。
5. 命名规范交给 [[smart-naming]]，本 skill 只负责「组织/归档/清理/去重」。
